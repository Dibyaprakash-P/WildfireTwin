# Scientific Consistency Audit

Date: 2026-10-01. Method: code reading (`ml/`, `simulation/`, `geo/`, `backend/`, `frontend/`), inspection of the
generated data and model artefacts, a repository-wide search for *FARSITE, FlamMap, Rothermel, MTT, WTRS, ground
truth, accurate, confidence, real-time, emergency, validated, physics-informed*, and re-running the evaluation.
Nothing was regenerated; the WTRS dataset and model checkpoints are unchanged.

## 1. Current architecture

```
OBSERVED DATA  FIRMS · ERA5 · SRTM · LANDFIRE · WorldCover · MTBS perimeters · Open-Meteo
        ↓
LOCAL ENVIRONMENTAL GRID  (128×128, EPSG:5070, 30/60/120 m by horizon)
        ↓
REFERENCE SIMULATION
   current : WTRS — Rothermel + MTT (internal)          → training / validation / test data
   optional: FARSITE / FlamMap import (external, offline) → separate benchmark dataset (none imported yet)
        ↓
U-Net · FNO · Physics-informed FNO   (trained on WTRS only)
        ↓
WildfireTwin inference (FIRMS footprint + Open-Meteo forecast) → 3D Cesium globe → dynamic re-forecast + alerts
```

**Research position (current version):** *WildfireTwin learns a neural surrogate of reference wildfire-spread
simulations generated by an internal Rothermel + minimum-travel-time pipeline (WTRS).* It is **not** a FARSITE
surrogate. A FARSITE-surrogate experiment is supported as a separate extension once real FARSITE output exists.

## 2. Actual reference simulation method

Verified in `simulation/rothermel.py`, `simulation/spread.py`, `simulation/reference.py` and in the data
(`scenarios.parquet → simulator = "WTRS-Rothermel-MTT"` for all 2,400 rows):

* Rothermel (1972) surface rate of spread; Scott & Burgan (2005) FBFM40 parameters; Albini (1976) live moisture of
  extinction; dynamic herbaceous curing; wind/slope vector combination; wind limit.
* Wind adjustment: Albini & Baughman (1979) for GR/GS/SH/SB, fixed 0.15 for TU/TL (assumption — no canopy layer).
* Anderson (1983) length-to-breadth ratio → elliptical spread.
* Minimum-travel-time growth: time-dependent Dijkstra on a 16-neighbour stencil with hourly weather.
* Surface fire only — no crown fire, spotting, suppression or fuel-moisture conditioning.
* No FARSITE/FlamMap code, binary or output is called or read anywhere in the generation path.

## 7. Scientific inconsistencies found

| # | Finding | Severity |
|---|---|---|
| 1 | No place labelled WTRS as FARSITE output (searched all code/docs/UI) — **no correction needed**; existing text already said "Rothermel + MTT … not FARSITE". | — |
| 2 | Spatial-block split leakage understated: docs said windows extend "a few km"; measured 54 % of test windows overlap some training window (90th pct overlap 90 %). | medium |
| 3 | MTBS described as "historical validation"; in code it only lists fires and displays perimeters — replay metrics use FIRMS footprints. | medium |
| 4 | Samples had no per-row `simulation_source`; only scenario-level `simulator` existed. Models did not record which reference engine they were trained on. | medium |
| 5 | Data page statuses were a static snapshot (not re-checked); FARSITE "Not present" was hard-coded; installed software and data were not distinguished. | low |
| 6 | Data page did not state whether each dataset is actually used in training (e.g. FIRMS appears central but is not a training input). | low |
| 7 | Replay panel badge "VALIDATED" could read as "model validated" — it is a single-case comparison. | low |
| 8 | Web import silently defaulted time units to minutes. | low |
| 9 | Models page did not state what the evaluation is measured against beyond one line; no leakage-controlled subset. | low |
| 10 | PI-FNO: physics loss is **genuine** (eikonal + irreversibility + non-burnable; logged every epoch; eikonal residual 1.11 → 0.30). Nuance: the reference data itself has residual ≈ 0.60, so the term is a consistency prior toward horizon-mean-weather spread, not evidence of higher physical fidelity. | note |

Claims checked and found supported: "decision-support research prototype / not an emergency warning system",
"physics-informed" (PI-FNO only), "not observed ground truth", absence of accuracy/confidence claims, "real-time"
not claimed (polling-based dynamic updates are described as such).

## 8. Corrections made

* Provenance columns (`simulation_source=WTRS`, `reference_engine=WTRS-Rothermel-MTT`, `simulation_method`,
  `source_version`) added to all 2,400 scenarios / 23,200 samples and the manifest — values of existing columns verified
  identical; backups kept (`*.pre_provenance.parquet`). Generator writes them for future datasets.
* `WildfireDataset` refuses datasets that mix reference engines.
* Training runs record a dataset card (name, version, source, method, region, temporal coverage, resolution,
  horizons, input variables, target) in checkpoint + `summary.json`; the model registry derives it for existing runs.
* Evaluation records `evaluated_against`, the reference dataset card, and a **strict no-overlap test subset**
  (2,308 samples); re-run on the same checkpoints. Growth IoU full → strict: U-Net 0.619 → 0.613, FNO 0.561 → 0.554,
  PI-FNO 0.578 → 0.573.
* Data page: live status per request, grouped *Observed / Simulated reference / External optional*, "Used in training"
  and verified roles per dataset, engine badges, separate "Installed research software" section (FlamMap detected).
* Models page: per-model *Training data*, *Reference method* (badge `SIMULATED · Rothermel + MTT`), *Physics-informed*
  yes/no; comparison states what it is evaluated against; strict-subset table.
* Simulation page: explicit *Reference engine* choice — `[ WTRS / Rothermel + MTT ]` vs `[ Import FARSITE / FlamMap ]`,
  engine-labelled results.
* Replay badge now "VALIDATED · single case vs FIRMS".
* Importer: provenance + SHA-256, explicit CRS option for `.asc` without `.prj`, exact frame derivation, required
  units; new `import_cli.py` and `build_dataset.py` (separate engine-named dataset versions).
* Documentation: this audit, `docs/wtrs_dataset.md`, `docs/farsite_flame_map_workflow.md`, README *Reference
  Simulation Methodology*, corrected split/MTBS statements in `docs/data_pipeline.md`, architecture diagram.

## 9. Remaining limitations

* Training targets are simulations of surface fire only (no crown fire, spotting, suppression).
* **Domain shift at inference:** models learn from simulated contiguous masks but are initialised from blocky
  375 m / 1 km FIRMS pixel footprints.
* Weather is spatially uniform per window; ERA5 (training) vs Open-Meteo (inference) differ in resolution and soil layer.
* No temporal hold-out (2024–2025 seasons in all splits); partial landscape overlap remains in the full test set
  (quantified; strict subset provided).
* Observed validation is single-case (historical replay vs FIRMS footprints); no statistical observed-data validation.
* FFWI-weighted sampling makes the dataset non-climatological.
* No uncertainty quantification.

## 10. Recommended future FARSITE experiment

1. In FlamMap 6, build a LANDFIRE LF 2025 landscape for the study area and run FARSITE for a set of ignitions/dates
   inside 2024–2025 (so ERA5 matches), exporting arrival-time grids with `.prj`.
2. Import each run (`import_cli.py`, with `--ignition-time`), then `build_dataset.py --split test` →
   `farsite-ncal-v1`.
3. Evaluate the existing WTRS-trained models on `farsite-ncal-v1` (cross-engine generalisation) — report it as
   "WTRS-trained model vs FARSITE reference", never as ground truth.
4. Optionally train a separate "FNO surrogate of FARSITE" on a FARSITE train split and compare with WTRS-trained
   models; keep both experiments and their datasets distinct.
